# 任务 T2：姿态感知与骨骼可视化（感知节点组 + 前端预览）

> ⚡ **v3 节点化适配 —— 本任务实现一组节点，不是一个程序**
> - `camera` 采集（发 `feature/frame.raw`，**永不跨机**）
> - `pose` 姿态 33 点（发 `feature/pose`）
> - `face` 面部 478 点 + 表情 + 头姿（发 `feature/face`）
> - `audio` 音量/事件（发 `feature/audio`）
> - `device` 设备枚举与热切换（发 `event/device`）
> - 路径：**`agent/nodes/<节点名>/`**（下文若见 `agent/controlled/perception/`，按此对照）
> - **`agent/core/devices.py`（M0 设备管理）由本任务实现** —— TF 只留桩，本任务独占
> - 必须继承 `agent/core/` 的 `Node` 基类 → 见 `TF-节点框架与消息总线.md`
> - 每个节点**独立进程** → 摄像头崩了不影响郊狼控制（这就是节点化的目的）

> **交付方**：任意 AI agent（可独立开工）
> **上位文档**：`docs/架构设计与路线图.md`（第五章 M1、6.1 实测结果）
> **优先级**：**P1，最高** —— 这是"以姿态识别为基础"的第一个可验证闭环
> **预估**：1~2 天

## 0. 一句话目标

摄像头 → MediaPipe → 结构化特征 → WebSocket → 浏览器 Canvas 骨骼动画。

## 5. `FeatureFrame` 规格（本任务的核心契约）

```jsonc
{
  "ts": 1719817201234,        // 毫秒时间戳
  "seq": 1024,                // 自增序号，丢帧检测用
  "pose": {
    "present": true,
    "landmarks": [            // 33 点，MediaPipe BlazePose 顺序
      [0.51, 0.33, 0.02],     // [x, y, z]，x/y 归一化 0~1，z 相对深度
      // ... 共 33 项
    ],
    "visibility": [0.99, 0.87, /* ... 33 项 */ ]   // 可选，用于前端淡显不可见点
  },
  "head": {                   // ← 需求 1b
    "yaw": 3.2, "pitch": -1.1, "roll": 0.4        // 角度，由面部矩阵换算
  },
  "face": {                   // ← 需求 1c（T6 实现，本任务只预留）
    "emotion": null,
    "confidence": null,
    "blendshapes": null
  },
  "audio": {                  // ← 需求 1e（T6 实现，本任务只预留）
    "level": null, "event": null, "text": null
  },
  "flags": { "dark": false, "absent": false, "silent": false }
}
```

**关键要求**
1. **骨骼点必须量化传输** —— 建议 x/y 各用 `uint16`（精度 1/65535，足够），或直接传浮点但保留 3 位小数。目标：**单帧 ≤ 300 字节**。
2. **帧协议与传输解耦** —— 本任务先用 **WebSocket**（`websockets` 或 FastAPI 的 WS），但 `FeatureFrame` 的序列化/反序列化要独立成函数，P3 换 WebRTC DataChannel 时不动。
3. **坐标归一化** —— 一律 0~1，前端自己乘画布尺寸，不要把像素坐标写进协议。

## 6. 对外接口

```python
# agent/controlled/perception/backends/base.py  —— 可插拔后端（重要！）
from abc import ABC, abstractmethod

class PoseBackend(ABC):
    """姿态模型抽象。默认实现是 MediaPipe；将来换 RTMPose/YOLO 只需新增一个实现。"""
    @abstractmethod
    def load(self) -> None: ...
    @abstractmethod
    def infer(self, frame_bgr) -> list[list[float]] | None:
        """输入 BGR ndarray，返回 33×3 归一化关键点，无人则 None。"""

# agent/controlled/perception/pipeline.py
class PerceptionPipeline:
    def __init__(self,
                 backend: PoseBackend | None = None,   # 默认 MediaPipe
                 camera_index: int = 0,
                 target_fps: int = 15,
                 width: int = 640, height: int = 480): ...

    async def start(self) -> None: ...
    async def stop(self) -> None: ...
    def latest(self) -> dict | None:
        """返回最新一帧 FeatureFrame（dict），供上层推送。"""

    # 事件回调：每产出一帧调用一次
    on_frame: Callable[[dict], None]
```

> `PoseBackend` 抽象是**硬性要求** —— 用户明确要求保留"换模型不伤上层"的能力。

## 6.5 设备管理与切换（**必做 —— 本机实测确实有多个设备**）

### 为什么必须做

本机实测（Windows 11）：

| 类型 | 实际存在的设备 |
|---|---|
| 摄像头 | `ACER HD User Facing`（笔记本内置）、`EOS Webcam Utility`（佳能相机当摄像头用） |
| 麦克风 | `麦克风阵列（Intel 智音）`、蓝牙耳机 `Haylou Purfree Lite`、USB 音频接口 |

而且**不只是摄像头/麦克风** —— BLE 设备（爪印、郊狼主机、心率带）同样会有多个，
所以设备管理要做成**通用设施**，放在 `agent/core/devices.py`，供 T1 / T4 / T7 / M9 / T5 共用。

### 技术方案（`sounddevice` 已装；`pygrabber` 需装）

```powershell
pip install --proxy http://127.0.0.1:7897 pygrabber
```

| 类型 | 枚举方式 | 打开方式 |
|---|---|---|
| 摄像头 | `pygrabber.dshow_graph.FilterGraph().get_input_devices()` → 拿**设备名** | `cv2.VideoCapture(index, cv2.CAP_DSHOW)`（顺序与 DirectShow 枚举一致） |
| 麦克风 | `sounddevice.query_devices()` → 名字 + hostapi + 输入通道数 | `sounddevice.InputStream(...)` |
| BLE | `bleak` 扫描（T1/T7/M9 各自实现） | 见各自任务书 |

### 实测数据与四个必须处理的坑（真机踩过，不是理论）

**摄像头（pygrabber）—— 本机 3 个：**
```
[index 0] ACER HD User Facing
[index 1] EOS Webcam Utility
[index 2] OBS Virtual Camera
```

**麦克风（sounddevice）—— 12 个条目，但只有 3~4 个物理设备：**
```
[0]  Microsoft 声音映射器 - Input         hostapi=0 MME         ← 映射器，应排除
[1]  麦克风阵列 (英特尔® 智音技术)        hostapi=0 MME         ← 默认输入
[4]  主声音捕获驱动程序                    hostapi=1 DirectSound ← 映射器，应排除
[5]  麦克风阵列 (英特尔® 智音技术)        hostapi=1 DirectSound
[9]  麦克风阵列 (英特尔® 智音技术)        hostapi=2 WASAPI 48k  ← 最优
[10] 麦克风阵列 1 ()                      hostapi=3 WDM-KS
[11] 麦克风阵列 2 ()                      hostapi=3 WDM-KS
[12] 麦克风阵列 3 ()                      hostapi=3 WDM-KS 16k
[13] 立体声混音 (Realtek HD Audio)         hostapi=3             ← 回环，不是麦克风
[16] 电脑扬声器 (...)                      hostapi=3             ← 输出设备
[19] 电脑扬声器 (...)                      hostapi=3             ← 输出设备
[20] 麦克风 (Realtek HD Audio Mic input)   hostapi=3
```

---

**坑 1：同一物理设备在 4 个 hostapi 下重复出现**（MME / DirectSound / WASAPI / WDM-KS）

直接列给用户会看到 12 个"麦克风"，完全无法理解。**必须去重**：

- 按设备名归一化归组
- 同组**优先取 WASAPI**（延迟最低、时钟最准），其次 DirectSound，最后 MME
- 排除映射器：`Microsoft 声音映射器`、`主声音捕获驱动程序`

**坑 2：`sounddevice` 列表里混有非麦克风项**

`max_input_channels > 0` **不够** —— "立体声混音"和"电脑扬声器"也会满足。还要按名字排除 `立体声混音` / `Stereo Mix` / `扬声器`，或明确标为「（回环）」而不是当作麦克风。

**坑 3：设备名含非 GBK 字符，直接 `print` 会崩** 💥

实测报错：
```
UnicodeEncodeError: 'gbk' codec can't encode character '\xae' in position 25
```
来源就是 `麦克风阵列 (适用于数字麦克风的英特尔® 智音技术)` 里的 `®`。

**解法（必须在程序入口做，不能靠运气）**：
```python
import sys
sys.stdout.reconfigure(encoding="utf-8", errors="replace")
sys.stderr.reconfigure(encoding="utf-8", errors="replace")
```
并且：
- `agent/core/logging.py` 的所有 FileHandler 显式 `encoding="utf-8"`
- JSON 落盘 / WS 发送用 `json.dumps(..., ensure_ascii=False)` 并以 UTF-8 编码
- 否则**设备名里有中文或符号就会炸**，而本机设备名**全都是中文**

**坑 4：摄像头 index 与设备名的对应关系会随插拔重排**

当前 `pygrabber` 的返回顺序 == `cv2.VideoCapture(index, cv2.CAP_DSHOW)` 的 index 顺序，**但这只在当前设备集合下成立**。
→ 所以持久化必须存**设备名**（稳定 ID），打开时**先枚举再定位 index**，不能存 index。

### 硬性要求

1. **必须用稳定 ID，绝不用 index**
   - 摄像头用**设备名**（或 DirectShow device path），麦克风用 `name + hostapi`
   - 理由：`index` 随插拔漂移 —— 用户今天选了 "EOS Webcam Utility"，明天可能就指向别的设备了
2. **运行时热切换**，不重启进程
   - 切摄像头：释放旧 `VideoCapture` → 打开新设备 → **重建 MediaPipe 的 timestamp 基准**
   - 切麦克风：停旧流 → 开新流
3. **热插拔感知**（建议做，可降级为轮询）
   - 定时（如 5s）重新枚举；变化时回调通知上层 → 推给前端
4. **持久化选择**：上次选的设备 ID 存配置，下次自动选中；设备不存在则回退到第一个可用并提示
5. **优雅降级**
   - 设备被占用（例如 `EOS Webcam Utility` 正被 OBS 用着）→ 报"设备忙"，**不要崩**
   - 一个摄像头都没有 → 允许用**视频文件**当输入源（便于无摄像头开发调试）

### 对外接口

```python
# agent/core/devices.py
from dataclasses import dataclass
from typing import Callable

@dataclass
class DeviceInfo:
    id: str            # ★ 稳定 ID（不是 index）
    kind: str          # "camera" | "microphone" | "ble" | "remote"
    name: str          # 展示名
    detail: dict       # 分辨率能力 / hostapi / RSSI 等
    available: bool

class DeviceRegistry:
    def list(self, kind: str | None = None) -> list[DeviceInfo]: ...
    def refresh(self) -> bool:
        """重新枚举；返回列表是否发生变化。"""
    def get(self, device_id: str) -> DeviceInfo | None: ...
    def on_change(self, cb: Callable[[list[DeviceInfo]], None]) -> None: ...

class CameraSource:
    """摄像头的打开/读取/热切换，屏蔽 index 细节。"""
    def __init__(self, registry: DeviceRegistry, device_id: str | None = None): ...
    def open(self) -> None: ...
    def read(self): ...                              # 返回 BGR frame 或 None
    def switch(self, device_id: str) -> None: ...    # ★ 热切换
    def close(self) -> None: ...
    @property
    def current(self) -> DeviceInfo | None: ...
```

`PerceptionPipeline` 增加三个方法：

```python
async def set_camera(self, device_id: str) -> None: ...
async def set_microphone(self, device_id: str) -> None: ...
def devices(self) -> dict:      # {"camera": [...], "microphone": [...]}  供前端拉取
```

### 前端（`web/pose-preview/`）

- 顶部两个下拉框：**摄像头** / **麦克风**，列出 `DeviceRegistry` 返回的设备名
- 切换后**立即生效**，无需刷新页面
- 不可用的设备置灰并标注原因

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| MediaPipe 抢 CPU，影响其他模块 | 降到 480p、`target_fps` 限制到 15；Pose 与 Face 交替推理（本任务只跑 Pose，Face 归 T6） |
| OpenCV 摄像头打不开（被其他程序占用） | 探测可用 index，给出清晰错误；支持"图片/视频文件"作为输入源便于无摄像头开发 |
| Windows 上 OpenCV 采集慢 | 用 `cv2.CAP_DSHOW` 后端；设置 `CAP_PROP_BUFFERSIZE=1` 减少延迟 |
| 前端 Canvas 绘制 33 点连线卡 | 用 `requestAnimationFrame` + 单帧覆盖，按 `seq` 丢弃过期帧（不要排队） |
