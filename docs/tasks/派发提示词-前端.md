> **给专职前端的开发 agent。** 这份文件同时是**接口手册**（照着调就行）和**派发指令**（边界在 §6）。

## 0. 一句话

大改 `web/` 这套控制面板，并加**串口下拉**。后端是现成的 `agent/nodes/web/`（FastAPI + WebSocket），**两边你都能改**。

## 2. 连接与生命周期

```js
// transport.js 已经在做，你改的时候别破坏这几条：
const url = (location.protocol === "https:" ? "wss://" : "ws://") + location.host + "/ws";
```

| 行为 | 现状 | 要求 |
|---|---|---|
| 地址 | **同源** `/ws`（后端 `8780` 同时托管页面） | 别改成硬编码端口 |
| 重连 | 失败后 `min(1000*retry, 5000)` 退避 | 保留 |
| 降级 | `file://` 直开、或重试 ≥2 次 → **切 mock**（`offline` 回调） | 保留（E10） |
| 连上 | 后端立刻发 `{"type":"hello","room":"local","ts":…}` | 用它显示房间名 |
| 补齐 | 后端把"最近一条"各类消息补发给新客户端 | 保留（不然刚打开是空的） |

## 3. 接口 A：浏览器 → 后端（发 `{op: …}`）

**统一走** `transport.send(obj)`：返回 `true` = 已发出；`false` = 离线（**调用方自己 mock 兜底**，见 `app.js:86`）。

| `op` | 字段 | 后端行为 | 回你什么 |
|---|---|---|---|
| `fire` | `waveform`(str) `channel`("A"/"B") `duration_ms`(int) `priority`(0/1/2) `overlay`(bool) + 强度三选一：`intensity_mode`("delta"/"abs"/"none") 配 `intensity_value`，或直接给 `intensity_delta` / `intensity` | 发 `command/fire` | `{"type":"ack","op":"fire","ok":true}` + 稍后一条 `fire`（审计回流） |
| `clear` | — | 发 `command/clear`（**急停**） | `{"type":"ack","op":"clear","ok":true}` |
| `select_device`（别名 `select`） | `kind`, `id` | 发 `command/select_device` | 无 ack；设备侧会回 `event/device` → 你收到 `devices` |
| | `kind` 取值：`camera` / `microphone` / `ble` / **`sim_coyote`**（假主机串口，见 §6）；`id` 是**稳定 ID**（设备名，不是 index） | | |
| `list_devices`（别名 `devices`） | — | 发 `command/select_device`（`action=list`）让 device 节点重报 | 稍后 `devices` |
| `waveforms` | — | 读波形表 | `{"type":"waveforms","waveforms":[…]}` |
| `import_waveform` | `name`, `version`(2/3/"auto"), `frames`(string[]) | 校验+落盘 `data/waveforms/` | `{"type":"waveforms","imported":{name,version,frames},…}` 或 `{"type":"import_error","error":…}` |
| `delete_waveform` | `name` | 删（官方波形拒删） | `{"type":"waveforms","deleted":name,"ok":bool,…}` 或 `import_error` |
| `rename_waveform` | `name`, `new_name` | 改名（官方波形拒改） | `{"type":"waveforms","renamed":{from,to},…}` 或 `import_error` |
| `ping` | — | — | `{"type":"pong","ts":…}` |

**各字段的合法值**（这些是"权威校验点"在别处，前端只做粗校验）：

- `waveform`：波形名（官方 24 条 + 用户导入的）；候选来自 `waveforms` 接口
- `channel`：`"A"` / `"B"`（后端会 `.upper()[:1]` 兜底）
- `duration_ms`：默认 `2000`
- `priority`：`0` 低 / `1` 中 / `2` 高
- `overlay`：`true` = **叠加**（不抢占对端已有任务），默认 `true`
- 强度：`intensity_delta`（相对增加，如 `10`）/ `intensity`（绝对设定 `0~200`）/ 都不给 = 只换波形不动强度

**示例**：

```js
transport.send({
  op: "fire",
  waveform: "TEASE_2",
  channel: "A",
  duration_ms: 1500,
  priority: 1,
  overlay: true,
  intensity_mode: "delta",
  intensity_value: 10,
});
transport.send({ op: "select_device", kind: "camera", id: "cam:ACER HD User Facing" });
```

## 4. 接口 B：后端 → 浏览器（收 `{type: …}`，在 `app.js:handleMessage()` 路由）

| `type` | 关键字段 | 前端现有处理 |
|---|---|---|
| `hello` | `room`, `ts` | 显示房间名（`app.js:143`） |
| `pose` | **紧凑格式**：`t`(ms) `s`(seq) `p`(0/1) `q`(base85 字符串) | `skeleton.setFrame()` · ⚠️ **不是浮点数组**，解码见 §5 |
| `face` | `emotion`, `confidence`, `head{yaw,pitch,roll}` | `updateEmotion()` + 给骨骼画头姿箭头 |
| `audio` | `level`(0~1), `event`("silent"/"sound"/"loud"), `text` | 声音卡（音量条 + 事件标签） |
| `heart` | `bpm`, `contact`, `rr_ms`, `device`, `mac` | 心率卡 + 迷你波形（`app.js:198`） |
| `pawprint` | 爪印事件（爪印节点未做，字段待定） | 暂未处理 |
| `devices` | 原样透传 `event/device`：`devices:[{kind, name, id, available?, detail?{loopback,internal}}]`、`selected:{kind:id}`、`mock?` | 三个下拉（`devices.js:34`） |
| `fire` | `ts`, `source`, `waveform`, `channel`, `duration_ms`, `version`, `frame_count`, `priority`, `overlay`, `client_id`, `slot_id` | 审计日志高亮一条 |
| `status` | `node`, `payload` | 顶栏"节点：…" |
| `topic` | `key`, `payload` | **兜底**：没被上面认领的 key 原样给你（调试用） |
| `waveforms` | `waveforms:[{name,source,version,frames}]` + 可选 `imported`/`deleted`/`renamed`/`ok` | 波形下拉 + 导入列表 |
| `ack` | `op`, `ok` | 现在只忽略；可以拿来做"已发送"提示 |
| `pong` | `ts` | 可用来算延迟 |

> **`_EPHEMERAL = {pose, audio, heart}`**：这三类**不进**"最近一条"快照 ——
> 新客户端连上时不会先收到一帧旧姿态。你要加新的高频类型，记得往这个集合里加（在后端）。

## 5. ✅ 骨骼数据：WS 下行是**已解码的数组**

> ⚠️ **本节上一版写错了**（我把 Zenoh 的线格式当成了 WS 下行格式），前端 agent 核对代码时抓到了，已更正。

后端 `_pose_payload()`（`node.py:254`）已经用 `frame_codec.FeatureFrame.from_wire()`
**把紧凑格式解码好了**，经 `/ws` 推给浏览器的是：

```js
{ type:"pose", ts:1730…, seq:812, present:true, landmarks:[[x,y,z], …33], visibility:[…] }
```

- `skeleton.js` **直接吃数组**，不需要 base85 解码；
- `present:false` → `landmarks` 为空数组（没检测到人）；
- 那个 `{t,s,p,q}`（量化 uint16 + base85、单帧 ≤ 300 字节）是 **Zenoh 上 `feature/pose` 的线格式**，
  由 web 节点负责解码 —— **面板侧看不到它，也不用管**。解码规则在 `agent/nodes/pose/frame_codec.py`。
- **结论（A）**：保持现状，**别动 `_pose_payload()`**。

## 6. 必做：串口下拉（本次明确要求）

**为什么**：假郊狼主机（`sim_coyote`）靠串口接 ESP32；机器上有多个串口，其中**蓝牙虚拟串口能打开成功但收不到字节**，必须让人选对。

**后端要加**（`agent/nodes/web/node.py`）：

- 新 op `list_ports` → 回 `{"type":"ports","ports":[…]}`，用
  `agent.nodes.sim_coyote.esp32_link.list_serial_ports()`（**已经有了**，返回对象带 `.to_dict()`）
- 每条至少含：`id`（建议 `serial:COM18`）、`name`（`COM18`）、`desc`（描述）、`hwid`、以及**能看出是不是蓝牙虚拟口**的信息

**前端要加**（`web/`）：设备卡里一行「假主机串口」下拉 →

```js
transport.send({ op: "select_device", kind: "sim_coyote", id: "COM18" });
```

> `id` 就是**串口名**（与 `agent/config.toml` 的 `[sim_coyote] port` 同格式）；
> 热切换由 `sim_coyote` 节点负责（**已实现，不重启节点**）。
> ⚠️ 蓝牙虚拟串口（`desc` 里带"蓝牙"/`hwid` 含 `BTHENUM`）要**标出来或置灰** —— 那是坑。
