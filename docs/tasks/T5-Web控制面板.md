# 任务 T5：Web 控制面板（`web` 节点 + 前端）

> ⚡ **v3 节点化适配 —— 本任务分两部分**
> - **后端节点**：`agent/nodes/web/` —— 订阅**全部** topic（`coyotelink/<room>/**`），转成 WebSocket 推给浏览器
> - **前端**：`web/`（原生 JS；`web/pose-preview/` 属 T2，别动）
> - 下文 `js/transport.js` 对接的**不再是"房间信封"**，而是**本机 web 后端**（后端再经 Zenoh 取数）
> - 必须继承 `agent/core/`（TF 产物）的 `Node` 基类

> **交付方**：任意 AI agent（可独立开工）
> **上位文档**：`docs/架构设计与路线图.md`（§2 需求、§5 M7）
> **优先级**：**P1 起就要有最小版**，随各模块推进逐步长全
> **预估**：最小版 1 天；全功能 3~4 天
> **依赖**：需要 T2（FeatureFrame）、T3（房间消息）、T4（郊狼指令）的消息格式 —— 已在各自任务书里定义，可先按契约开发，用 mock 数据联调

---

## 0. 一句话目标

一个**单页 Web 面板**，让控制者能：

1. **看到** —— 被控者的骨骼动画、头部朝向、表情标签、声音事件、心率
2. **控制** —— 手动开火波形、调强度、急停、配置判定规则
3. **感知状态** —— 连接状态、谁在房间里、指令审计日志
4. **隐私**：面板收到的是**结构化 JSON**，永远不存在视频/音频元素

**技术约束：原生 HTML/CSS/JS + Canvas，不引入 React/Vue 等框架**（只画线段，不需要框架负担）。

## 4. 板块设计

### 4.1 骨骼舞台（核心视觉，需求 1a/1b）

- `<canvas>` 用 **Canvas 2D** 画：
  - **33 个关节点** + 骨架连线
  - MediaPipe `POSE_CONNECTIONS` 定义的连线关系（0-11-12-... 的躯干、四肢链）
  - **头部朝向**：在头部用一个小箭头/三角表示 `head.yaw/pitch/roll`（需求 1b）
  - `visibility < 0.5` 的点**淡显或隐藏**
- **坐标**：一律把归一化 `[0,1]` 乘画布宽高，不要假设像素坐标
- **帧丢弃策略**：用 `requestAnimationFrame` 渲染，`seq` 比当前小的直接丢，**不排队**（否则会越描越滞后）
- 显示 **FPS** 和 **端到端延迟**（用 `frame.ts` 与本地时间差）

### 4.2 状态条（需求 1c/1e/3）

横向卡片：**表情** · **声音** · **心率** · **连接状态**

| 卡片 | 数据来源 | 展示 |
|---|---|---|
| 表情 | `FeatureFrame.face.emotion` + `confidence` | 文字标签 + **emoji/表情包**（需求 1c 原话："以文字或表情包的形式显示"） |
| 声音 | `FeatureFrame.audio.event` + `text` | 音量条 + 事件标签（如"淫叫/求饶"）+ 识别文字 |
| 心率 | `event` 类消息 | 数值 + 实时折线（Canvas 或 SVG） |
| 连接 | room 状态 | 对端角色、地址、延迟 —— 对应需求 7"看到谁访问了" |

### 4.3 控制区（需求 2b）

| 控件 | 行为 |
|---|---|
| **波形选择** | **官方波形 + 导入的自定义波形**（数量**运行时读取**，不要写死 24/25）；显示中文名，标注来源（官方/导入）与格式版本（V2/V3） |
| **📥 导入波形** | ★ 支持 **V2 / V3 两种格式**，见下方 §4.3.1 |
| **通道** | A / B 单选 |
| **时长** | 滑块（0.5s ~ 30s） |
| **叠加/抢占** | 开关 → 发 `overlay` 字段（**默认叠加**） |
| **🔥 开火按钮** | 大按钮，触发一次 `fire` |
| **强度** | A/B 各自滑块（绝对/相对切换） |
| **🛑 急停** | **常驻红色大按钮**，一键 `clear()` 全通道 + 清空本地排队 |

> ⚠️ 急停按钮必须在**任何状态下都可见可点**（固定定位），不要藏在折叠面板里。

#### 4.3.1 波形导入（⭐ 用户明确要求：**V2 / V3 两种格式都要能导入**）

支持两种输入方式，都接受两种帧格式：

| 输入方式 | 说明 |
|---|---|
| **粘贴文本** | 一个文本框，每行一帧（支持 `#` 注释、空行） |
| **选择文件** | `.json` 或 `.txt` |

| 要求 | 说明 |
|---|---|
| **自动识别格式** | 6 个 hex 字符/帧 → **V2**；16 个 → **V3**。也可手动强制指定 |
| **导入后立即生效** | 出现在波形下拉里，标注 `[导入·V3]` / `[导入·V2]` |
| **错误提示要精确** | 帧长混用 / 非法 hex → 明确提示**第几帧**出错，不要只说"格式错误" |
| 可管理 | 导入的波形能**删除 / 重命名** |
| 只读官方 | 官方波形（`COYOTE_WAVEFORMS`）不可删除 |

**与后端的契约**（帧格式细节见 `T4-郊狼V4控制端.md` §4.6）：

```jsonc
// 导入
{ "type":"coyote", "payload": {
    "op":"import_waveform", "name":"我的波形", "version":3,
    "frames":["0A0A0A0A00000000", "..."] } }

// 拉取全部可用波形（官方 + 导入）
{ "type":"coyote", "payload": { "op":"list_waveforms" } }
// 返回：[{ "name":"气泡", "source":"official", "version":3 }, { "name":"我的波形", "source":"imported", "version":2 }]
```

> 导入后**不要在前端做格式校验就完事** —— 后端 `waveform_io.py` 才是权威校验点，前端只做基本提示。

### 4.4 规则编辑器（需求 2a）

- 简单表单式（先不做拖拽）：
  ```
  规则名：____
  条件：[警戒线|维持姿势|按钮|心率阈值]  参数：____
  动作：[开火] 波形：____ 通道：__ 时长：__ 优先级：__
  冷却：__ 秒
  ```
- 规则存在**控制端**（因为判定在控制端，见决策 §11 #7）
- 列表展示 + 启停开关 + 单条删除

### 4.5 审计日志（需求 7 延伸）

- 滚动列表：`时间 · 方向 · 类型 · 摘要`
- **开火记录必须高亮**（谁/何时/哪个波形/多久）
- 支持导出（下载 JSON）

### 4.6 设备选择（⭐ 用户明确要求）

**背景**：被控端机器上通常有**多个摄像头和多个麦克风**（本机实测就有 `ACER HD User Facing` +
`EOS Webcam Utility` 两个摄像头，`Intel 麦克风阵列` + 蓝牙耳机 + USB 音频多个输入）。
BLE 设备（爪印 / 郊狼主机 / 心率带）同样会有多个。所以面板必须能选。

**要求**

| 项 | 说明 |
|---|---|
| 设备下拉框 | 摄像头 / 麦克风各一个，外加 BLE 设备列表（爪印、心率带） |
| **用名字展示** | 不要显示 "Camera 0"，要显示 `EOS Webcam Utility` |
| **稳定 ID** | 前端提交的是 `DeviceInfo.id`，不是 index（见 T2 §6.5） |
| **热切换** | 选择后立即生效，不刷新页面、不重连房间 |
| 不可用置灰 | 设备被占用/断开时置灰并标原因 |
| **热插拔** | 设备插入/拔出时列表自动更新（后端推送 `devices_changed` 事件） |
| 记住选择 | 刷新页面后仍选中上次的设备 |

**协议（与 T2/T3 的契约）**

```jsonc
// 后端 → 前端：设备列表变化时推送
{ "type":"event", "payload": { "ev":"devices", "devices": {
    "camera":     [{ "id":"camera:ACER HD User Facing", "name":"ACER HD User Facing", "available":true }, ...],
    "microphone": [{ "id":"mic:Intel...|MME", "name":"麦克风阵列 (Intel 智音)", "available":true }, ...],
    "ble":        [{ "id":"ble:AA:BB:CC:DD:EE:FF", "name":"DGLAB-XXXX", "available":true }]
} } }

// 前端 → 后端：切换设备
{ "type":"event", "payload": { "ev":"select_device", "kind":"camera", "device_id":"camera:EOS Webcam Utility" } }
```

> 本任务**消费**这套接口；枚举逻辑在 T2 的 `agent/core/devices.py` 里实现。
> 若 T2 尚未就绪，前端先用 mock 设备列表开发。

## 5. 对接的协议（契约来自其他任务书）

### 5.1 连接（T3 信封）

```jsonc
{ "v":1, "room":"AB12CD", "from":"B", "seq":1234, "ts":1719817201234,
  "type":"feature", "payload": { /* FeatureFrame（T2） */ } }
```
可用 `type`：`hello` / `role` / `ping` / `pong` / `feature` / `coyote` / `event` / `bye`

### 5.2 骨骼（T2 `FeatureFrame`）

```jsonc
{ "ts":..., "seq":..., "pose": { "present":true, "landmarks":[[x,y,z]×33] },
  "head": {"yaw":..,"pitch":..,"roll":..}, "face": {...}, "audio": {...} }
```

### 5.3 开火（T4）

```jsonc
{ "type":"coyote",
  "payload": { "op":"fire", "waveform":"PULSE", "channel":"A",
               "duration_ms":2000, "priority":1, "overlay":true } }
```

### 5.4 开发期怎么办

**在 T3/T4 完成前用 mock**：`js/mock.js` 里造一个假的 FeatureFrame 生成器（让一个虚拟骨架摆动）+ 假的对端。
**面板必须能在"无后端"状态下演示**，这样前后端可以并行开发。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 后端还没好，前端没法调 | **mock 优先**（§5.4），面板先跑起来 |
| Canvas 画 33 点 + 连线在低端机掉帧 | 单帧覆盖式重绘、避免每帧创建对象；必要时降级为 30 帧/秒节流 |
| 消息风暴导致 UI 卡 | 渲染与数据处理解耦：**只渲染最新帧**，历史只用于日志 |
| 时间戳不同步，延迟显示不准 | 用 `seq`+本地到达时间估算，不要假设时钟同步；显示"相对延迟"即可 |
